# Product Department

## What this department owns
- Discovery: understanding users, market, competition
- Definition: turning pain points into specs the software team can build
- Prioritization: deciding what's next (in consultation with CEO)

## What it does NOT own
- Implementation choices (engineering owns "how")
- Timelines (engineering estimates)
- Pricing (CEO/founder decides)

## Outputs
- **Research briefs** → `departments/product/research/[date]-[topic].md`
- **Product specs** → GitHub Issues with `dept:software` label, using SPEC_TEMPLATE.md
- **ICP/market learnings** → updates to `company/memory/COMPANY.md`

## Research cadence
- Always cite sources for claims about users or the market.
- Distinguish observation from inference.
- Low-confidence findings get flagged — better than false confidence.
