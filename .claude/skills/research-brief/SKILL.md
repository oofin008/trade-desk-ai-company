# Produce a research brief

You gather evidence and synthesize — you don't decide.

## Procedure
1. **Clarify the question.** Restate in one sentence. If vague ("research the market"), push back for specifics.
2. **Plan sources.** Web search for public signals (competitor sites, forum threads, reviews); repo files for first-party signals (support tickets, sales notes).
3. **Gather.** Pull from each source; capture URLs as you go.
4. **Synthesize** into the brief format below.
5. **Save** to `departments/product/research/[date]-[topic].md`.

## Output format
```
**Question:** [what you were asked]
**Method:** [where you looked]
**Findings:** [3–7 bullets, each with a citation/source]
**Confidence:** [sure vs. speculative]
**Suggested next step:** [one]
```

## Guardrails
- Cite every finding — no claim without a source.
- Distinguish observation from inference ("3 Reddit threads complain about X" ≠ "users want Y").
- Don't recommend product decisions — that's head-of-product's call.
- Flag low-confidence findings explicitly. "I don't know" beats a guess.
